## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier and isolated environment (ST1–ST6, RUN1, RUN10, ENV6):** the primary path performs no clone, repository install or repository import, and installs nothing into the notebook kernel. Section 2 writes the package's 4 modules, the stage runner, the hash lock compiled from the `pyproject.toml` pins (`uv pip compile pyproject.toml --python-version 3.12 --python-platform x86_64-manylinux_2_28 --generate-hashes --only-binary :all:`), the 3-file snapshot manifest and `LICENSE` into a run directory and verifies each against its SHA-256; a pinned `uv` wheel builds a managed CPython 3.12.12 environment from the lock with `--require-hashes`, reused per lock digest, and every learner cell runs one stage in its own process (`MPLBACKEND=Agg`, no inherited `PYTHONPATH`/`PYTHONHOME`/`PYTHONSTARTUP`). `metadata.dimer.generated_from` records the repository, the generating revision, the package SHA-256, the carried-file digests and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when a carried file differs from the repository, when the lock does not pin every runtime pin with hashes, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition:** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent (`README.md`, `model-config.yaml`, `model.ckpt`), from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry; `from_pretrained(device='cpu', weights_dir=...)` hands the verified directory to `tirex2.load_model`, which reads the two loader files from it directly. The checkpoint is a PyTorch `.ckpt` deserialised by upstream `tirex2` with `weights_only=True`; the trust boundary is the digest-verified file at the pinned revision (see `../docs/WEIGHTS.md`).
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/tirex_forecasting_input_manifest.json` with the schema, ceilings (`MIN_CONTEXT`, `MAX_CONTEXT`, `MAX_HORIZON`), per-variate observations, verdict, and one recorded rejection finding (a too-short context); `evaluation_report` (EVAL21) writes `outputs/tirex_forecasting_evaluation_report.json` — `sample-sanity` with `mae`, `rmse`, `interval_coverage` (q10–q90) and the `last_value_baseline` on the chronologically withheld truth, `not-measurable` (with what would make the task measurable) when no truth is supplied.
- The default sample is a deterministic synthetic trend + seasonal series generated in code (no download); its metrics are sanity evidence for the input contract, the holdout plumbing and the forward pass, not a correctness or benchmark claim.
- Forecasting obligations (Notebook Specification §20.3): chronological order is preserved, the final horizon is withheld, no future target reaches the model, horizon and effective context are printed, q=0.5 is stated to be a model median, the other quantiles are described as model quantiles rather than confidence intervals, and the last-value baseline and a least-squares trend + season reference are compared on the same holdout; on the synthetic series the noise floor is printed too, and the notebook says that the trend + season fit is about as accurate as the model there.
- CPU is the reference path because upstream CUDA execution compiles fused recurrent kernels on first use and needs a CUDA toolkit; the model stages hide any GPU (`CUDA_VISIBLE_DEVICES=''`) before importing torch, so a visible GPU without a toolkit cannot break the load.
- BYOD CSV headers are inspected before pandas ingestion so duplicate columns cannot be silently renamed; the delimiter is detected (comma, semicolon, tab); text values in a target column are refused naming the column; empty values are refused with their line numbers; timestamps must parse and be unique, increasing and regularly spaced; a series longer than `MAX_CONTEXT + HORIZON` keeps its most recent rows and the trim is reported. `BYOD_CSV_PATH` works in any runtime and the Colab upload is guarded. `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
