# TiRex-2 Forecasting Pipeline

DIMER-oriented zero-shot forecasting wrapper for **NX-AI TiRex-2**, supporting univariate and multivariate targets plus optional past and future-known covariates through the upstream open inference API.

## Upstream alignment

- Model: `NX-AI/TiRex-2`
- Revision: `05e5b26db52bfb256f1ae1bdf785589850482de3`
- Runtime package: `tirex-2==0.2.1`
- Weight license: Apache-2.0
- Open-release capability: zero-shot forecasting; **no task-specific fine-tuning in this repository**
- Quantile output: 0.1 through 0.9 in 0.1 increments; median is q=0.5

## Public API

```python
from tirex_forecasting_pipeline import TiRexForecastPipeline

pipe = TiRexForecastPipeline.from_pretrained(device="cpu")   # loads the digest-verified weights/tirex-2/ snapshot
result = pipe.forecast([1, 2, 3, 4] * 16, horizon=12)
print(result["median"])
```

## Weights layout

```
weights/tirex-2/
  dimer-base-manifest.json   # modelId, revision, per-file bytes + sha256 (verified on every load)
  model-config.yaml          # TiRex-2 architecture config read by tirex2.load_model
  model.ckpt                 # 380613375 bytes, git-ignored (PyTorch checkpoint, read once to convert)
  model.safetensors          # 380555776 bytes, git-ignored, produced locally by convert_checkpoint (served)
```

`from_pretrained()` calls `stage_missing_files()` then `verify_snapshot()` and refuses to load if any file is missing or its SHA-256 differs from the manifest; `allow_download=True` fetches only the absent manifest entries at revision `05e5b26db52bfb256f1ae1bdf785589850482de3`. `ensure_converted()` then reads `model.ckpt` once with `torch.load(weights_only=True)` and writes `model.safetensors`, whose SHA-256 must equal `CONVERTED_SHA256`; the model is built from `model-config.yaml` and loaded from that file with `load_state_dict(strict=True)`. Without a snapshot manifest it refuses, whatever `allow_download` says (there is no Hub-direct load). To stage the snapshot by hand: `hf download NX-AI/TiRex-2 --revision 05e5b26db52bfb256f1ae1bdf785589850482de3 --local-dir weights/tirex-2` (the manifest is committed).

For covariate-conditioned forecasting, the DIMER wrapper enforces the upstream time-axis contract before model execution: `past_covariates` must have exactly the target context length, while `future_covariates` must contain exactly `context_length + horizon` steps. Both accept shape `(n_covariates, time)` or a one-dimensional single-covariate input and must contain finite values.

`tutorials/tirex_forecasting_colab.ipynb` is declared `TASK-INFERENCE` and `GUIDED` under DIMER Notebook Specification 2.2 and is **standalone** (§4): generated by `tools/build_notebook.py` (/3), it carries the package's four modules, the stage runner, a hash-locked requirements file and the manifest, so the exported notebook runs without this repository (parity enforced by `tests/test_notebook_parity.py`). Nothing is installed into the notebook kernel: a pinned `uv` builds an isolated environment and each stage runs in its own process, so `Run all` needs no restart. Its default path generates a deterministic synthetic series in code, withholds the final horizon chronologically, surfaces the pipeline ceilings, resolves the pinned checkpoint through the public API, forecasts on the CPU with the q=0.5 median as the point forecast, scores `mae`/`rmse`/`interval_coverage` against a last-value baseline and a least-squares trend + season reference through `evaluation_report`, validates BYOD CSVs before pandas ingestion, and exports JSON plus an aligned CSV. BYOD is optional and gated off by default. See `tutorials/README.md` for the registry and `docs/release-verification.md` for the release gate.
